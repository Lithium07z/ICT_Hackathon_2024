# AIR Explorer

### AI + AR 기반 양양 여행 추천 및 체험 애플리케이션

**2024 강원 ICT 이노베이션스퀘어 AI 해커톤 출품작**

AIR Explorer는 **AI 기반 맞춤형 여행 추천**과 **AR 기반 현장 관광 경험**, **지역 스탬프 및 리더보드**를 결합하여 관광객의 지역 탐방을 유도하고 지역 관광 활성화를 목표로 제작한 모바일 여행 애플리케이션 프로토타입입니다.

본 저장소는 AIR Explorer 전체 시스템 가운데 **Unity 기반 AR 관광 체험 모듈**을 포함하고 있습니다.

# 📌 프로젝트 소개

AIR Explorer는 단순히 관광지 정보를 검색하는 기존 여행 앱에서 한 단계 더 나아가,

**여행 계획 → 현장 탐방 → AR 체험 → 스탬프 수집 → 여행 기록**

으로 이어지는 여행 경험을 하나의 서비스 안에서 제공하는 것을 목표로 했습니다.

프로젝트는 특히 축제나 관광 성수기에 지역을 방문한 관광객이 특정 유명 장소에만 머무르지 않고 주변의 관광지, 음식점, 카페, 숙박 시설까지 자연스럽게 탐방하도록 유도하는 **이벤트형 관광 플랫폼**을 지향합니다.

AR 콘텐츠와 스탬프 수집 같은 게임 요소를 활용해 관광객의 적극적인 참여를 유도하고, AI를 활용해 사용자의 취향에 맞는 여행 코스를 제공하는 방식입니다.

---

# 💡 기획 배경

프로젝트에서는 양양이 다양한 자연 관광 자원과 액티비티를 보유하고 있지만 관광객이 일부 유명 장소에 집중되고, 상대적으로 알려지지 않은 장소나 지역 상권으로 관광 수요가 충분히 확산되지 않는다는 문제의식에서 출발했습니다.

이에 따라 다음 두 가지 접근을 결합했습니다.

### AI 기반 여행 계획

사용자의 여행 스타일과 선호도를 입력받아 LLM을 통해 적합한 장소들을 추천하고, 여러 관광지를 하나의 여행 코스로 구성합니다.

### AR 기반 현장 경험

실제 장소를 방문한 사용자에게 AR 콘텐츠와 관광 정보를 제공하고, 해당 장소를 방문했다는 기록을 스탬프 형태로 저장합니다.

이를 통해 여행 전에 사용하는 **추천 서비스**와 여행 중 사용하는 **체험 서비스**를 하나의 사용자 경험으로 연결하는 것이 AIR Explorer의 핵심 아이디어입니다.

# ✨ 핵심 기능

## 🤖 1. LLM 기반 맞춤형 여행 코스 추천

사용자가 대화형 인터페이스를 통해 원하는 여행 스타일을 입력하면 LLM이 이를 바탕으로 양양 지역의 장소들을 추천합니다.

예를 들어 다음과 같은 요구를 전달할 수 있습니다.

```text
저는 해변을 좋아하고 자연을 보는 것을 좋아합니다.
숙소는 반드시 해변 근처였으면 좋겠고
식사는 로컬 음식점을 포함해 주세요.
```

추천 결과는 단순한 장소 목록이 아니라 여러 장소를 방문하는 **여행 코스** 형태로 제공하도록 설계했습니다.

추천된 장소는 지도에서 확인할 수 있으며 각 장소를 선택하면 상세 관광 정보를 확인할 수 있습니다.

> 이 기능은 AIR Explorer 전체 시스템에 포함된 기능이며, 현재 GitHub 저장소의 Unity 프로젝트에는 LLM 및 지도 클라이언트 코드는 포함되어 있지 않습니다.

---

## 🗺️ 2. 추천 여행 경로 지도 시각화

AI가 추천한 관광지를 지도 위에 표시하여 사용자가 여행 동선을 직관적으로 확인할 수 있도록 설계했습니다.

지도에서는 다음과 같은 정보를 확인할 수 있습니다.

* 추천 방문 장소
* 여행 코스 순서
* 관광지 위치
* 음식점 및 카페
* 숙박 시설
* 장소별 상세 설명

시연 버전에서는 여러 추천 장소를 연결한 경로를 지도 위에 표시하고, 각 마커를 선택하면 장소 이름과 상세 정보를 확인할 수 있도록 구현했습니다.

---

# 📱 3. AR 관광 가이드

본 저장소에서 구현된 핵심 기능입니다.

Unity의 **AR Foundation**을 이용하여 실제 환경의 이미지 마커를 추적하고 해당 장소에 연결된 AR 콘텐츠를 표시합니다.

AIR Explorer의 프로토타입에서는 단순한 이미지 인식만 사용하는 것이 아니라

```text
GPS 위치
    +
AR 이미지 마커
```

두 정보를 함께 검사합니다.

따라서 등록된 마커를 아무 장소에서나 스캔한다고 콘텐츠가 표시되는 것이 아니라 사용자가 실제 해당 관광지 주변에 있는지를 GPS로 확인한 뒤 AR 콘텐츠를 활성화합니다.

---

# 🐤 4. AR 관광 가이드 캐릭터 「해키」

AIR Explorer에서는 관광 정보를 단순한 텍스트 UI로만 보여주는 대신 AR 캐릭터 **해키**를 관광 가이드로 활용했습니다.

사용자가 관광지의 AR 마커를 인식하면 실제 카메라 화면 위에 해키가 등장합니다.

```text
관광지 도착
    ↓
GPS 위치 확인
    ↓
AR 마커 스캔
    ↓
해키 등장
    ↓
관광지 정보 제공
```

해키를 통해 관광 안내를 하나의 캐릭터 경험으로 제공함으로써 일반적인 관광 정보 앱보다 친근하고 기억에 남는 사용자 경험을 만드는 것을 목표로 했습니다.

---

# 🔎 5. GPS + AR 마커 이중 검증

AR 콘텐츠는 `ARTrackedImageManager`를 통해 등록된 Reference Image를 인식합니다.

마커의 이름은 관광 데이터의 `id`와 연결됩니다.

예:

```text
attraction_1
attraction_2

accommodation_1

restaurant_1
```

이미지가 인식되면 다음 조건을 확인합니다.

```text
Marker ID == Location ID
```

그리고 현재 GPS 좌표와 장소의 등록 좌표를 비교합니다.

프로토타입의 위치 판정 기준은 다음과 같습니다.

```text
|현재 위도 - 장소 위도| < 0.002°
|현재 경도 - 장소 경도| < 0.002°
```

두 조건을 모두 만족할 경우에만 AR 콘텐츠를 생성합니다.

---

# 🧍 6. AR 캐릭터 배치 및 추적

마커와 위치가 모두 검증되면 AR 이미지의 Transform 하위에 캐릭터 Prefab을 생성합니다.

```text
ARTrackedImage
      │
      └── Yangyang Character
```

이미지의 위치와 회전이 변경되면 캐릭터의 Transform도 함께 갱신되어 실제 마커 위에 캐릭터가 존재하는 것처럼 보이게 합니다.

AR 마커 추적이 사라질 경우 앱은 다시 Scan 상태로 돌아갑니다.

---

# 📖 7. 관광지 상세 정보

AR 콘텐츠를 바라보면 해당 장소의 설명을 확인할 수 있습니다.

각 장소 데이터는 다음과 같은 구조로 관리됩니다.

```json
{
  "id": "attraction_1",
  "place": "낙산사",
  "address": "강원특별자치도 양양군 강현면 낙산사로 100",
  "phone": "033-672-2448",
  "type": "attraction",
  "lat": 38.12461,
  "lng": 128.628,
  "text": "관광지 상세 설명"
}
```

Unity에서는 이 데이터의 `id`와 AR Reference Image 이름을 연결하여 어떤 정보를 출력할지 결정합니다.

---

# 🗃️ 8. 양양 관광 데이터셋

해커톤을 위해 양양 지역의 관광 데이터를 직접 수집·정리하여 서비스 데이터로 사용했습니다.

첨부된 데이터셋은 총 **80개 장소**로 구성되어 있습니다.

| Category             |  Count | 예시              |
| -------------------- | -----: | --------------- |
| 관광지 (`attraction`)   |     20 | 낙산사, 하조대, 서피비치  |
| 숙박 (`accommodation`) |     20 | 쏠비치 양양, 낙산비치호텔  |
| 음식점 (`restaurant`)   |     20 | 송이버섯마을, 영광정메밀국수 |
| 카페 (`café`)          |     20 | 쏠티캐빈, 플리즈웨잇     |
| **Total**            | **80** |                 |

각 데이터에는 다음 정보가 저장되어 있습니다.

```text
id
place
address
phone
type
lat
lng
text
```

이 구조를 유지하면서 지역 데이터만 교체하면 양양뿐 아니라 다른 지역의 관광 서비스로도 확장할 수 있도록 설계했습니다.

---

# 🔊 9. 관광 음성 안내

텍스트 설명뿐만 아니라 장소별 음성 안내도 제공합니다.

Unity의 `TTSManager`는 현재 인식된 장소의 이름과 AudioClip을 연결하여 해당 관광지의 음성을 재생합니다.

프로토타입에서는 다음 기능을 지원합니다.

* 관광 안내 재생
* 음성 일시 정지 및 재생
* 남성 / 여성 안내 음성 변경
* 장소별 안내 AudioClip 선택

즉 런타임에서 텍스트를 즉석 합성하는 방식보다는, 시연용으로 제작한 장소별 음성 콘텐츠를 Unity에서 재생하는 구조입니다.

---

# 📸 10. AR 스탬프 및 방문 기록

AIR Explorer의 중요한 게임화 요소 중 하나입니다.

관광지에서 AR 콘텐츠를 정상적으로 인식하면 해당 시점의 카메라 화면을 캡처합니다.

Unity에서는 다음 흐름으로 동작합니다.

```text
AR Marker 인식
      ↓
GPS 위치 검증
      ↓
AR 콘텐츠 생성
      ↓
카메라 화면 Capture
      ↓
PNG Encoding
      ↓
Server Upload
```

`RenderTexture`를 이용해 카메라 프레임을 캡처하고 PNG로 변환한 뒤 `UnityWebRequest`를 이용해 서버로 전달합니다.

시연 애플리케이션에서는 이 결과를 이용해 해당 장소를 방문했다는 **스탬프와 사진 기록**을 사용자 프로필에서 확인할 수 있도록 구성했습니다.

---

# 🏅 11. 스탬프 가이드

사용자가 방문할 수 있는 장소를 스탬프 형태로 보여줍니다.

방문하지 않은 장소는 잠금 상태로 표시되고, 해당 장소에서 AR 체험을 완료하면 방문 기록이 해제되는 구조입니다.

이를 통해 사용자가 유명 관광지만 방문하는 것이 아니라 주변의 여러 관광 명소를 계속 탐색하도록 유도합니다.

스탬프에는 방문 당시의 사진과 장소 정보를 함께 남겨 여행 후에도 기록으로 확인할 수 있습니다.

---

# 🏆 12. 리더보드

수집한 스탬프 수를 기반으로 사용자 순위를 계산하여 리더보드에 표시합니다.

```text
User
 │
 ├── Stamp 1
 ├── Stamp 2
 ├── Stamp 3
 │
 ↓
Stamp Count
 │
 ↓
Leaderboard
```

스탬프 경쟁을 통해 관광객의 탐방 참여도를 높이고 행사나 축제에서 게임처럼 즐길 수 있는 이벤트 요소를 제공하는 것이 목적입니다.

# 💬 13. 해키와 함께하는 여행 가이드

시연 애플리케이션에서는 해키를 AR 캐릭터뿐 아니라 여행 서비스의 가이드 캐릭터로도 활용합니다.

사용자는 대화형 인터페이스에서 자신의 여행 취향을 전달할 수 있으며, 추천 결과는 실제 양양 관광 데이터와 연결되어 여행 코스와 장소 설명으로 제공됩니다.

이를 통해

```text
AI 여행 추천
      ↓
지도에서 여행 코스 확인
      ↓
실제 장소 방문
      ↓
해키 AR 체험
      ↓
스탬프 획득
```

이라는 전체 여행 경험을 구성했습니다.

해커톤에서 제작한 AIR Explorer 전체 시스템은 크게 세 영역으로 구성했습니다.

# 🔄 Unity AR 상태 구조

Unity AR 모듈은 기능을 여러 Mode로 분리해 관리합니다.

```text
Startup
   │
   ├── AR Supported
   │        ↓
   │      Scan
   │        │
   │   Marker Found
   │        ↓
   │      Main
   │        │
   │   Tracking Lost
   │        └────────→ Scan
   │
   └── AR Unsupported
            ↓
          NonAR
```

### Startup

AR Session 초기화 상태와 단말의 AR 지원 여부를 확인합니다.

### Scan

GPS 위치를 확인하고 주변 관광지를 탐색하면서 AR 이미지 인식을 수행합니다.

### Main

마커와 위치를 검증한 후 캐릭터 및 관광 콘텐츠를 표시합니다.

### NonAR

AR을 지원하지 않는 환경에서 대체 화면을 표시합니다.

# 🚀 실행 환경

프로젝트는 다음 Unity 버전에서 제작되었습니다.

```text
Unity 6000.0.26f1
```

Android Build Support 환경이 필요하며 실제 AR 기능을 테스트하려면 ARCore를 지원하는 Android 기기를 사용하는 것을 권장합니다.

프로젝트에 설정된 최소 Android API Level은 다음과 같습니다.

```text
Android API Level 24
Android 7.0+
```

앱 실행 시 위치 기반 기능을 위해 Android Fine Location 권한을 요청합니다.

# ⚠️ 현재 공개 저장소 사용 시 주의사항

본 저장소는 해커톤 시연을 위해 제작된 프로토타입의 Unity AR 부분입니다.

### ARCore Extensions

`Packages/manifest.json`의 ARCore Extensions가 당시 개발 PC의 로컬 파일 경로를 참조하고 있습니다.

따라서 새로운 환경에서 프로젝트를 열 경우 패키지 경로를 현재 환경에 맞게 수정해야 할 수 있습니다.

### Backend Endpoint

AR 체험 완료 후 스크린샷을 서버로 전송하는 코드는 남아 있지만 공개 저장소에서는 원래 서버 주소가 제거되어 있습니다.

따라서 스탬프 서버 연동을 다시 사용하려면 별도의 Backend Endpoint가 필요합니다.

### 전체 AIR Explorer 실행

이 저장소에는 다음 구성요소가 포함되어 있지 않습니다.

```text
Flutter Application
Django Backend
AWS Infrastructure Configuration
LLM Configuration
Google Maps API Configuration
```

따라서 저장소 단독으로는 해커톤에서 시연된 AIR Explorer 전체 서비스를 그대로 재현할 수 없으며, **Unity AR 모듈의 구현 및 구조를 확인하기 위한 저장소**로 보는 것이 정확합니다.

### 관광지 인식 방식

기획 자료에서는 "카메라로 관광지를 비추면 관광지를 인식한다"고 표현되어 있지만, 공개된 Unity 프로토타입에서는 일반적인 AI Object Recognition이 아니라 **AR Foundation의 Reference Image Tracking + GPS 위치 검증 방식**으로 구현되어 있습니다.

# 🌱 활용 방안 및 기대 효과

AIR Explorer는 양양 한 지역에 한정된 서비스보다는 관광 데이터를 교체하여 다른 지역에도 적용할 수 있는 지역 관광 플랫폼을 목표로 했습니다.

스탬프와 리더보드를 이용한 게임화는 관광객이 여러 장소를 직접 탐방하도록 유도하고, AI 여행 추천은 잘 알려지지 않은 관광지·음식점·카페 등이 여행 코스에 자연스럽게 포함될 수 있도록 지원합니다.

이를 통해 다음과 같은 효과를 기대했습니다.

* 관광객 참여 및 재방문 동기 강화
* 지역 내 여러 관광지로 방문객 분산
* 지역 음식점·카페·숙박 시설 노출 확대
* 관광지와 지역 축제의 스토리텔링 강화
* AR을 이용한 몰입감 있는 관광 경험
* 스탬프 수집을 통한 다양한 여행 코스 탐방
* 지역 행사 및 축제의 이벤트 마케팅 활용
* 지역별 관광 데이터 교체를 통한 전국 단위 확장

# 🎯 Project Goal

AIR Explorer가 해결하고자 했던 핵심 질문은 다음과 같습니다.

> **"관광객에게 지역을 직접 탐험하고 싶은 동기를 어떻게 만들 수 있을까?"**

AI는 **어디를 여행할 것인지** 결정하는 것을 돕고,

AR은 **그 장소에서 무엇을 경험할 것인지** 제공하며,

스탬프와 리더보드는 **다음 장소로 이동할 동기**를 제공합니다.

AIR Explorer는 이 세 가지 경험을 연결하여 관광을 단순한 정보 검색이 아닌 **직접 참여하고 기록하는 지역 탐험 경험**으로 만드는 것을 목표로 제작되었습니다.
